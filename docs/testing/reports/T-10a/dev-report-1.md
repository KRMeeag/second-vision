## Design decisions the Lead should know

1. **Pre-import (criterion 2).** `conftest.py` imports `gi`/`Gst`/`GLib` (via `gst_helpers.load_gst`) and then
   `hailo`, `hailo_apps...buffer_utils`, `hailo_apps...gstreamer_app` at import time. pytest loads
   `tests/conftest.py` before importing any test file, so the stand-ins' `setdefault` calls become no-ops. If the
   bindings are missing (Poetry), nothing is imported and the stand-ins work as before. The first version of the
   probe failed silently in `my_hailo_env` (it read `gi.repository.Gst` as an attribute before importing it, and
   my own first suite run showed `295 passed` with the pre-import actually failing); it now imports
   `gi.repository.Gst` / `GLib` by full name, and `PREIMPORT` is printed in the pytest header
   (`sv-harness real modules pre-imported: ...`) so a silent failure is visible.
2. **Timeout method (criterion 3): `signal`, plus a GLib guard.** Measured on this Pi in `my_hailo_env` with
   throw-away tests that hang on purpose (`--timeout=2` or `3`):

   | A test stuck in | `signal` method | `thread` method | With this harness (`signal` + guard) |
   |---|---|---|---|
   | `time.sleep`, busy loop, `Event().wait()`, libc `sleep`/`pause` via ctypes | fails with `Timeout (>Ns) from pytest-timeout`, run continues | process exits with `os._exit(1)`, nothing after it runs | fails, run continues |
   | `GLib.MainLoop().run()` | **hangs until killed** (PyGObject 3.50 never lets Python run the signal handler) | process exits, no summary | **fails at the limit with `a GLib main loop was still running at the test's time limit`, run continues** |
   | `g_main_loop_run` called through ctypes (stands for a native call that never returns and ignores signals) | **hangs until killed** | process exits | **still hangs until killed. NOT bounded.** |

   `thread` cannot satisfy "fails and the run goes on" because it kills pytest, so the default is `signal`
   (set in `conftest.pytest_configure`, only when pytest-timeout is installed and the user gave no `--timeout`,
   `PYTEST_TIMEOUT` or ini value). The autouse `_glib_main_loop_guard` fixture patches `GLib.MainLoop.run` for the
   duration of each test, attaching a timeout source to the loop's own context 0.5 s before the limit, so the loop
   quits and the test fails. **Residual gap (R4):** a thread blocked in native code that ignores signals and is
   not `GLib.MainLoop.run()` (a driver call that never returns, a loop run through ctypes) is not stopped by this
   harness. Only `@pytest.mark.timeout(N, method="thread")` ends that, and it ends the whole run with a stack
   dump. The guard reads `config._env_timeout`, a private attribute of pytest-timeout 2.4.0; if a future version
   renames it, the guard silently turns off, and `test_a_stuck_glib_main_loop_fails_at_the_time_limit_and_the_run_goes_on`
   would then fail and say so.
3. **Case table, mixed results (criterion 6).** The brief defines all-pass, any-fail and all-skip only. When some
   of a case's tests passed and some were skipped I report `SKIP (partial: 1 passed, 1 skipped: <reason>)`, never
   PASS, because part of the case did not run (R5). The Lead may want a different rule.
4. **`camera_unplug` and `sudo`.** The class runs exactly `sudo -n <tool> status`, `... detach camera --for N` and
   `... attach camera`, with `<tool>` = `REPO_ROOT/.claude/tools/usb_sim.py` resolved from `conftest.py`'s location.
   "Check with the tool's `status`" is implemented as running `sudo -n <tool> status`: that is the only way to learn
   whether `sudo -n` would ask for a password, and it is an allowed shape. `sudo` appears in the harness exactly once,
   `SUDO_LAUNCHER = ("sudo", "-n")`, which a test pins. All unit tests use a fake tool with the launcher replaced
   by `(sys.executable,)`; none runs sudo. Teardown (`restore`) always runs `attach camera`, then waits (bounded,
   20 s) for the recorded nodes, or any node `status` lists if the numbers changed; if the camera does not come
   back, the test ends in an ERROR that says so.
5. **Skip location.** Skips raised from the conftest hook show `tests/conftest.py:NNN` as their location in `-rs`.
   Each test is still named in `-v`, in the JUnit XML and in the evidence log's case table.
6. **Addition not in the brief:** `uat_evidence.py` passes anything after a bare `--` to pytest unchanged
   (for example `-- -m "not device"`). I needed it to run the whole suite without the real unplug test.
